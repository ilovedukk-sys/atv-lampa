# ATV Lampa — суть проекта

Аналог медиацентра **Lampa** для телевизора **LG webOS** с интерфейсом, максимально повторяющим
**приложение Apple TV (tvOS 18/26)**: боковая стеклянная панель, Top Shelf с кадром на весь экран,
полки карточек, фокус с увеличением и параллаксом, экран фильма, страница актёра, звуки навигации.
Данные о фильмах — **TMDB** (главный источник); по желанию — оценки и факты **Кинопоиска** (ключ в «Настройках»).
Видео — через **TorrServer** (готово), Jellyfin — следующий этап.

## Пользователь
- Новичок в программировании, общается **по-русски**. Код пишет Claude, пользователь проверяет на ТВ.
- Объяснять просто, давать готовые команды, по возможности делать всё самому (Windows, терминал — PowerShell).
- Пользователь смотрит этот ТВ — **не запускать замеры/перезапуски, если на экране его приложение**
  (`com.ott.drm` — его IPTV). Проверить: `npx ares-launch --device tv --running`.

## Телевизор (целевое устройство)
- **LG 49UK6300PLB, webOS 4.4.3** (Chromium 53, слабый 4-ядерный ARM, 843 МБ памяти), IP **192.168.0.11**.
- Рутован, стоит **Homebrew Channel** (Developer Mode не нужен). SSH: `root@192.168.0.11`, ключ `~/.ssh/webos_tv`.
- В утилитах LG устройство называется `tv`. Инструкция по подключению — `TV.md`.
- Код должен работать в **Chromium 53**: без flex `gap`, `inset`, `aspect-ratio`, `isIntersecting` (проверять `intersectionRatio`),
  `backdrop-filter` только через `@supports` (есть с webOS 6). Сборка — только legacy (`@vitejs/plugin-legacy`, `renderModernChunks: false`).

## Стек
Vite + **Preact** + TypeScript, без UI-библиотек. Вёрстка всегда в 1920×1080 (main.tsx масштабирует под окно).
**На ТВ приложение работает в 720p** (`public/appinfo.json`: `"resolution": "1280x720"`, с 27.10.2026): окно 1280×720,
сцена уменьшена в 1,5 раза, телевизор растягивает картинку сам. Видеочипу втрое меньше точек — главная +8–10 fps;
текст чуть мягче (сравнение — `screenshots/compare-1080-720.png`). Вернуть 1080p — `"1920x1080"` в appinfo.json.
Видео в плеере играет и в 720p (проверено: время идёт, размер видео 1280×720 = всё окно).
Ключ TMDB — в `.env.local` (`VITE_TMDB_KEY`, не коммитить, попадает в сборку — не публиковать .ipk). Шаблон — `.env.example`.
TorrServer пользователя: **http://192.168.0.15:8090** (MatriX.141; в `.env.local` как `VITE_TORRSERVER_URL`, меняется в «Настройках»).
Встроенный поиск раздач в нём выключен; парсер (Jackett/jacred) пользователь может указать в «Настройках».
Для проверки в TorrServer лежит тестовая раздача «Sintel» (Blender, CC-BY, хеш 08ada5a7…), TMDB movie:45745 — `?open=movie:45745`.

## Команды
```
npm run dev            # http://localhost:5173 (стрелки, Enter, Esc; ?open=movie:603 — сразу экран фильма, ?open=person:6384 — актёр)
npm run tv             # сборка → .ipk → установка → запуск на ТВ
npm run tv:screenshot  # снимок экрана ТВ в screenshots/
npm run tv:bench       # автозамер FPS на ТВ по сценариям (таблица на экране + снимок)
```
Профилирование на ТВ (сначала туннель `ssh -i ~/.ssh/webos_tv -N -L 19998:127.0.0.1:9998 root@192.168.0.11`):
`node scripts/trace.mjs` (на что уходит время кадра), `node scripts/layers.mjs ["CSS-опыт"]` (слои отрисовки),
`node scripts/tv-eval.mjs "key(37)"` (выполнить JS / нажать кнопку пульта в приложении),
`node scripts/profile.mjs "<сценарий>"` (профиль JS по функциям; имена видны в сборке `PROFILE=1 npm run tv`, потом вернуть обычную).
Перед замерами проверять `top` на ТВ: оборванные SSH-команды (`grep -r`, `find /`) остаются работать и съедают ядро — так однажды
«пропало» 5–8 fps. Долгие поиски по ФС ТВ запускать с `timeout`.
Для опытов с трейсом запускать приложение с `{"still":1}` (`npx ares-launch --device tv com.atvlampa.app -p '{"still":1}'`):
Top Shelf не листается сам — иначе смена слайда посреди трейса путает цифры. Опыты, вставляющие CSS/JS в живое приложение,
могут сломать отрисовку (однажды пропал кадр Top Shelf) — перед итоговыми выводами перезапускать приложение.
A/B-замер варианта CSS (пишем его под `html.exp`): `BENCH_PARAMS='{"exp":"ab"}' BENCH_WAIT=200 npm run tv:bench`.

## Структура `src/`
- `core/focus.ts` — движок фокуса (замена tvOS Focus Engine): стрелки по геометрии, только соседние ряды,
  экраны (`data-screen`), боковая панель (`data-sidebar`: влево с края/«Назад» — открыть, вправо — вернуться),
  прокрутка через transform (`data-scroll-x/-y`, `data-section`), стек «Назад», звуки.
- `core/` — `parallax` (наклон за Magic Remote, отблеск), `lazy` (ленивая загрузка + подгрузка заранее по ходу),
  `quality` (качество обложек), `lite` (уровень эффектов: все / облегчённый `html.lite` / минимальный `html.lite.ultra`),
  `sound`, `fps`, `library` (медиатека в localStorage), `bench`.
- `api/tmdb.ts` — запросы, кеш в localStorage, перевод в `Item`; `api/details.ts` — экран фильма и сезоны.
- `data/catalog.ts` — полки вкладок Главная/Фильмы/Сериалы/Детям; `data/mock.ts` — данные без ключа TMDB.
  Top Shelf «Фильмов» — только фильмы, «Сериалов» — только сериалы, оба без мультфильмов/детского (`isForKids` по `genreIds`);
  «Детям» — TMDB discover с `certification.lte=PG` (US), мультсериалы — жанр 10762. Кеш списков — ключ с префиксом `v2`.
- `components/` — `Sidebar`, `Browse` (вкладка с Top Shelf), `Hero`, `ShelfRow`, `Card`, `Artwork`, `Details`,
  `GenreScreen`, `LibraryView`, `SearchView` (экранная клавиатура), `SettingsView`, `TextInput` (ввод адресов),
  `About` (внизу экрана фильма, как в Apple TV: «Описание» — карточки, «Информация / Языки / Создатели» — панели),
  `Sources` (выбор раздачи → файлы/серии), `Player` (плеер tvOS: полоса времени, перемотка, субтитры .srt, панель ↓).
- Трейлеры (`core/trailer.ts`, `core/webos.ts` — luna через `PalmServiceBridge`): TMDB `videos` (русские первыми) →
  кнопка «Трейлер» и полка «Трейлеры» → запуск `youtube.leanback.v4` с `contentTarget: https://www.youtube.com/tv?v=KEY`.
  Встроить плеер YouTube нельзя (file:// без Referer). webOS при запуске YouTube закрывает наше приложение (мало памяти),
  поэтому перед запуском пишем `returnTo` в localStorage и при следующем старте открываем тот же фильм (≤30 мин).
  YouTube после холодного старта сначала спрашивает профиль — это его поведение.
- Страница актёра (`components/PersonScreen.tsx`, `api/person.ts`): TMDB `/person/{id}` + `combined_credits`, имя по-русски из
  `also_known_as`, биография (нет русской — английская), полки «Известность» (по числу оценок), «Режиссёр», «Фильмы», «Сериалы»
  (без ток-шоу, «Self» и архивных кадров). Фон — спокойный цвет из фото. Открывается из «Актёры и съёмочная группа»
  (в конце ряда — режиссёры/создатели). Окно «ЕЩЁ» — общий `components/Overlay.tsx`: длинный текст листается ↑/↓.
- Кинопоиск (`api/kinopoisk.ts`) — **по желанию**: ключ kinopoiskapiunofficial.tech в «Настройках» (localStorage `kpKey`,
  по умолчанию `VITE_KP_KEY`; пусто — выключено; 500 запросов/сутки). Фильм ищем по IMDb id из TMDB (у сериалов —
  `external_ids`), без него — по названию и году. 4 запроса на фильм, кеш `kp1:` на неделю. Показываем: КП и IMDb в строке
  под названием, карточку «Кинопоиск», «Знаете ли вы, что…» (факты без спойлеров), сборы в России; TMDB главный —
  с КП берём только то, чего нет в TMDB (описание, слоган, возраст), и страны по-русски (`withKp`). Грузится после анимации
  открытия, в «разогреве» — нет. С ТВ сервер доступен (проверено: ответ 401 на пробный ключ — TLS и CORS в порядке);
  с настоящим ключом не проверено — у нас его нет, вывод проверен на образце ответа из документации API.
- `api/torrserver.ts` — API TorrServer (запросы text/plain без preflight); `api/releases.ts` — раздачи из TorrServer,
  парсера Jackett и встроенного поиска TorrServer, разбор качества и серий; `core/history.ts` — «Продолжить».
- Стек экранов в `App.tsx`: details → sources → player (фильм из одного файла: плеер заменяет sources).
  Плеер перехватывает кнопки в capture-фазе на window; под плеером остальные экраны `visibility: hidden`.
- `styles/app.css` — все стили (с комментариями «почему так» по замерам), `tokens.css` — токены и стекло.

## Правила производительности (выяснены замерами на этом ТВ — соблюдать!)
- Карточки максимально простые: **не слои** (никаких `will-change`, 3D-transform, даже `perspective()` у обычных карточек),
  минимум позиционированных элементов. Картинка — `background-image` у `.art__bg`, тень — `box-shadow` у рамки.
- **Никаких постоянных анимаций** (Ken Burns уронил прокрутку 56→18 fps; любая бесконечная анимация держит ТВ на 60 кадрах в покое).
  Медленные индикаторы — JS ~5 раз/с без transition.
- Не смешивать лишние полноэкранные слои; не прятать главную под экраном фильма (пересчёт стилей ~1500 элементов).
- Не анимировать `box-shadow`, размытые `text-shadow` на крупном тексте, проявление каждой картинки.
- Тяжёлые эффекты — под `html.lite` (облегчённый режим). Любое изменение интерфейса — проверять `npm run tv:bench`.
- Минимальный режим (`html.ultra`, `isUltra()`): без transition/animation вообще, теней и стекла; обложки всегда низкого
  качества; Top Shelf не листается сам; без разогрева, без предзагрузки фонов, меньше подгрузки заранее, без наклона.
  Замер 26.10.2026 (эффекты/облегч./миним.): вниз по полкам 33/35/56, открыть фильм 15/33/48, вниз к сериям 28/39/57.
  `tv:bench` теперь три столбца — ждать `BENCH_WAIT=170`.
- Вертикальная прокрутка ограничена низом страницы (последний ряд у низа экрана); `.page__end` — 120px.
- Главная как в tvOS 26 (по видео пользователя с настоящего Apple TV): кадр Top Shelf (`[data-scroll-follow]`)
  едет вверх вместе со страницей, первая полка встаёт на 430px (`data-stick`), под полками — спокойный цвет из кадра
  (`tintOf` в core/color.ts: w300 → canvas 16×9 → HSL, яркость 30%), низ кадра переходит в этот цвет.
  Размытый слой (`backdrop__soft`) и гашение названия при прокрутке убраны. Видео-превью в Top Shelf
  не сделано: прямых ссылок на ролики нет (YouTube не встраивается), а видео под интерфейсом слабому ТВ не по силам.
  Замер 26.10.2026 после этого: вниз по полкам 31/33/56, назад на главную 55/55/57, смена слайда 43/45/53.
  Замер 26.10.2026 (актёры, Кинопоиск; до распаковки заранее): вниз 36/35/57, вверх 35/36/59, постеры 48/47/60,
  открыть фильм 16/39/50 (худший кадр 350 мс — первое открытие), вниз к сериям 32/42/57, назад 52/54/58, смена слайда 42/45/54.
  После распаковки заранее (26.10.2026): вниз 34/33/57, вверх 33/35/58, постеры 51/51/60, открыть фильм 15/36/49
  (худший кадр 250 мс), вниз к сериям 37/41/58, серии 48/48/59, назад 55/55/57, смена слайда 47/45/51.
  Заметно выросла только смена слайда с эффектами (42 → 47); первое открытие фильма по fps то же — его держит JS
  (~30 мс на нажатие) и первая раскладка экрана, а не картинка.
- **Куда уходит время (трейсы 27.10.2026).** Узкое место — видеочип: поток GPU занят ~75% при прокрутке главной.
  Половина — рисование кадра: полноэкранный слой кадра Top Shelf стоит ~10 мс на кадр (когда едет — ~17 мс),
  слои страницы и полок дешевле. Картинка поменьше/canvas вместо img/непрозрачный фон — не помогают (проверено).
  Вторая половина — растр: браузер ТВ растеризует на видеочипе и при анимации увеличения ПЕРЕРИСОВЫВАЕТ слой карточки
  на каждом кадре своей анимации (~25 раз за фокус — растр идёт и без обновлений главного потока). Тень, скругление, блик, кривая «пружины» на это не влияют
  (проверено); без анимации увеличения растр 530 → 190 мс, но её не убираем — это вид Apple TV.
  Программный растр включить нельзя (принудительно включён в webOS).
- **Слои при фокусе** (27.10.2026): анимируемая карточка/кнопка поднимается `z-index` (классы is-focused/was-focused),
  полки не позиционированы. Без этого каждое нажатие выносило в слои и перерисовывало хвост полки и соседние полки;
  слоёв на главной 35 → 25. A/B: вниз/вверх по главной +2–3 fps. Сдвиг полки через CSS-переменную пробовали
  и убрали: пересчёт стилей всех карточек полки, серии −4 fps (а слоёв без неё столько же).
  Подписи карточек прячутся `visibility`, а не `opacity: 0` (−90 «слоёв» в расчётах браузера, главный поток −10%).
- Опыт «кадр Top Shelf внутри страницы» (один слой вместо двух): fps не изменился — не повторять.
- Счётчик замера считает кадры главного потока (requestAnimationFrame). Анимации transform идут в отдельном
  потоке, поэтому на экране бывает плавнее, чем в таблице, — когда главный поток занят (серии: ~12 мс на пересчёт
  слоёв каждый кадр, т.к. главная со всеми слоями остаётся под экраном фильма).
- **Главная не перерисовывается** при открытии фильма и смене слайда (полки — useMemo в Browse.tsx), нижние разделы
  экрана фильма — тоже (useMemo в Details.tsx). JS при открытии фильма 101 → 34 мс.
- Замер 27.10.2026 (после всего этого; ТВ перед этим перезагружен): вниз 43/37–39/57, вверх 41/40/59, постеры 54/56/60,
  открыть фильм 23–30/46/51 (худший кадр 183–200 мс), вниз к сериям 24–28/40/56, серии 43/43/55, назад 57/59/58,
  смена слайда 46/47/55. «Вниз к сериям» в столбце «Эффекты» — первый заход на экран фильма (растр новых рядов), дальше ~41.
  Вчера при той же программе было на 5–8 fps хуже: ТВ работал 18 ч, память в swap, нагрузка ~9. **Перезагрузка ТВ
  заметно ускоряет приложение** — сравнивать замеры только в одном состоянии ТВ.
- **Замер 27.10.2026 в 720p** (эффекты/облегч./миним.): вниз 51/53/58, вверх 52/52/58, постеры 53/54/60,
  открыть фильм 32/48/53, вниз к сериям 39/49/57, серии 43/45/55, назад 59/58/59, смена слайда 54/55/53.
  В 720p постеры и кадры карточек берутся на ступень меньше (core/quality.ts): w342 → w185 — точек всё равно меньше.
  Таблица замера и счётчик FPS в 720p выглядят крупнее (они вне масштабируемой сцены) — это нормально.
- `npm run tv:bench` закрывает и снова запускает приложение. Однажды запуск сразу после закрытия потерялся — на экран вернулось
  IPTV пользователя. Теперь `scripts/tv.mjs` ждёт закрытия, проверяет запуск и повторяет; если не вышло — замер отменяется.
- Текущие цифры (эффекты/облегчённый, 25.10.2026): прокрутка 56–60, по главной вниз-вверх 32–37, постеры 44–53,
  открытие фильма 20–24/39, вниз к сериям 23–26/36–38, назад на главную 47–52/53.
  Разброс между прогонами ±4 fps (зависит от свободной памяти ТВ).
- «Открыть фильм» в столбце «Эффекты» — это ПЕРВОЕ открытие после запуска (холодный JS + новые картинки),
  повторное ~36–39 и с эффектами (выплывание текста почти бесплатно — проверено опытом, `{"exp":1}`).
  Поэтому: через 2 с после загрузки главной экран фильма один раз строится скрыто («разогрев», App.tsx),
  а задержка на карточке 0,7 с заранее скачивает подробности и фон (core/prefetch.ts).
- **Распаковка заранее** (`core/predecode.ts`): JPEG-кадр 1280×720 браузер ТВ распаковывает 100–150 мс в момент первой
  отрисовки — это и был главный рывок при открытии фильма и смене слайда. Теперь кадр заранее рисуется в слой 1×1
  (почти прозрачный, поверх всего — под непрозрачным экраном браузер его не распаковывает): при задержке на карточке
  0,7 с (prefetch) и следующий слайд Top Shelf. Трейс на ТВ: распаковка при открытии 103 мс → 0. Держим 2 картинки.
- Опыт «прятать главную под экраном фильма» (`visibility: hidden`): открытие и прокрутка экрана фильма без изменений,
  возврат на главную 55 → 47. Не повторять. Под экраном фильма видеочип и так упирается в лимит памяти
  («tile violates memory policy» в трейсе) — это фон, а не причина рывков.
- Цвет из картинки (`tintOf`) берётся по адресу с `?tint`: TMDB шлёт CORS-заголовок только на запрос с Origin, и картинка,
  уже стоящая на карточке, лежит в кеше без него — холст её не читает. Для фото людей — размер `w45`.
- Заглушки (`artImage`) кешируются по цветам палитры, а не по id. Нижние разделы экрана фильма строятся после
  анимации открытия (450 мс). Большие подложки — сплошным цветом (сплошные тайлы не растеризуются).

## Кнопки пульта

## Заметки
- Проект в git (ветка `main`, первый коммит — этапы 1–4). `.env.local` с ключом TMDB не коммитится.
- Мелкие недоделки: «Профиль» в панели без имени; блик карточек отключён на главной (по вкусу пользователя);
  Кинопоиск на странице актёра не используется (только TMDB).
- Трейс по времени: `TRACE_OUT=файл.json node scripts/trace.mjs …` сохраняет сырые события (в них: `RasterTask` с layerId,
  `CommandExecutor:PutChanged` с decoder — DisplayCompositor = рисование кадра, RenderWorker = растр);
  `LAYERS_SIZES=1 node scripts/layers.mjs` — размеры слоёв, их id и элементы.
